Code generation beyond mainstream languages

When AI writes 75% of code, what happens to our DSLs?

At Google Cloud Next ’26, Google CEO Sundar Pichai announced that over 75% of new Google code is now generated by AI. As autonomous AI agents rapidly transform software development in mainstream languages like Python and Java, a critical question arises for the Model-Driven Engineering (MDE) community: What happens to our Domain-Specific Languages (DSLs)?

Unlike mainstream programming languages backed by massive training corpora, low-resource DSLs (such as OCL and Alloy) face severe data scarcity, preventing standard scaling laws from automatically solving code quality issues. Moreover, traditional binary pass/fail unit testing creates a diagnostic blind spot that conceals whether an LLM possesses latent syntactic knowledge of a DSL.

In this talk, we introduce a systematic assessment framework designed to evaluate and improve LLM code generation for low-resource DSLs. Our framework measures LLM’s knowledge of the target language by first considering a use case, and then it finds the best combination of prompting techniques and parameters to improve code quality.

We evaluated it on over 90,000 code generation tasks, we share concrete takeaways for the MDE community: why model selection dominates prompt engineering for DSLs, how simple prompt templates minimize token costs without sacrificing accuracy, and why combining multi-attempt sampling with error-driven code repair yields the largest performance gains for domain-specific constraints.
